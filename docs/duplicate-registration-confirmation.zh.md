# 同号登记确认（2026-10-15）

需求来源：用户提供的 Jeff 微信截图，用户已确认理解正确。

## 行为

- 登记保存时按现有规则检查“公司＋订单号”，忽略首尾空格和大小写；检查包括已核销历史订单。
- 没有同号历史记录时直接保存。
- 有同号历史记录时，保存前弹窗列出重复号码，询问是否继续登记为独立新订单。
- 取消时整批不写入，保留表单内容以便修改。
- 确认后保存为独立订单，原记录不受影响。
- 一批包含新号码和重复号码时，先确认再保存整批，避免取消后只保存了一部分。
- 后端在 SQLite 写事务中检查当前数据，不依赖页面缓存。确认后沿用原提交标识，重复提交仍不会重复新增。
- CSV/SQLite 导入逻辑保持现有行为，本次确认限于手工登记入口。

## 修改位置

- `src/lib/db.ts`：登记接口增加可选确认检查，在整批写入前返回重复号码。
- `src/app/actions.ts`：手工登记启用检查，向前端返回确认提示；确认后才允许同号新增。
- `src/app/components/workbench.tsx`：显示浏览器确认弹窗，取消保留表单，确认后重试原提交。
- `src/lib/types.ts`：增加操作结果中的确认标记。
- `scripts/test-duplicate-orders.mts`：补充取消无写入、确认新增、混合批次、号码标准化、跨公司及重复提交测试。
