## v0.1.31 的操作方式

1. 搜索订单号，在同号记录中选择要处理的那一笔。
2. 在“订单详情”顶部右侧点击红色“删除误登记订单”。电脑和手机均使用这个固定入口。
3. 确认弹窗列出公司、订单号、登记日期和数量，说明本笔登记及客户先交要求会移除，订单总数和待交数量会减少，无法在页面上撤销。取消不会修改数据。
4. 仅无实际交货且处于待核销状态的订单允许删除。已有交货、已核销、返厂、只读云端都保留入口，点击会解释不能删除的原因。
5. 页面展示后订单又被修改时拒绝删除，并要求刷新核对。
6. 删除后可以重新登记，同号的其他订单保持独立。

## 云端同步与发布顺序

旧同步合并会保留“仅云端有”的记录，因此只新增桌面删除按钮不够。本次增加按不可变订单 ID 保存的删除记录：删除在 SQLite 即时事务中完成，保存删除前内容指纹和时间戳；自动同步会将删除同步给云端。

云端仅在原订单内容、时间戳匹配且没有实际交货时执行同步删除；否则保留云端订单并进入冲突处理。已有云端删除记录会阻止旧桌面备份恢复原 ID；同号新 ID 不受影响。完整替换也不能使用缺少云端删除记录的旧快照绕过此保护。

为避免桌面已经删除而手机仍显示，已配对的桌面会先检查云端 `/api/health` 的 `capabilities.orderDeletionSync === 1`。旧云端或无法联网时，本次删除会被拦截并弹窗解释。

发布顺序必须是：

1. 发布验证过的 v0.1.31 镜像；在 OCI 先执行数据库备份，再更新固定镜像版本并重建应用容器，保留环境文件、云端只读设置及数据挂载。
2. 核对健康接口返回 v0.1.31 和删除同步能力。
3. 发布 Windows v0.1.31 安装包，让 Jeff 从“软件更新”升级，或运行安装包覆盖安装。无须卸载旧版，安装器排除 `data/`、`logs/`。
4. 让 Jeff 检查版本与按钮，实际误登记订单由 Jeff 核对后自行删除；不要用正常生产订单试删。

OCI 当前维护路径为 `/home/ubuntu/jeff-order/docker-compose.yml`，镜像固定在 `:0.1.29`。GitHub 的镜像工作流不会自动更新 OCI，重启 Jeff 电脑或仅拉取 latest 都不能完成部署。
